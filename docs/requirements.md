# 校园二手交易网站需求文档

## 1. 项目目标与范围

### 1.1 项目目标

为校园用户提供一个网站，让大家可以浏览、搜索、发布和管理二手商品。第一版重点是让发布者能展示商品信息，让有兴趣的用户能找到商品并通过约定的方式联系发布者。

### 1.2 MVP 范围

MVP（最小可行产品）是第一版能够投入使用、用来验证核心需求的产品。本版聚焦账号、商品信息、搜索浏览、收藏和商品管理。交易的付款、物流和纠纷处理暂不由平台完成。

本文中标为“待决定”的事项需要产品负责人确认后才能成为确定需求。

## 2. 用户角色与权限

| 角色 | 主要权限 |
| --- | --- |
| 未登录访客 | 浏览和搜索在售商品、查看商品详情；不能发布或收藏。是否允许查看联系方式待决定。 |
| 注册用户 | 登录、浏览和搜索、收藏／取消收藏、查看自己的收藏；发布商品并管理自己发布的商品。 |
| 商品发布者 | 注册用户的商品管理身份。可编辑、下架自己的商品；不能修改或下架他人的商品。 |
| 管理员 | 处理用户举报和违规商品、隐藏或删除违规内容、管理账号。管理员的具体操作范围和审计要求待决定。 |

权限必须由服务器核实，不能只依赖网页是否显示某个按钮。

## 3. 第一版 MVP 功能清单

### 3.1 纳入第一版

- **账号**：注册、登录、退出登录；必要的账号信息校验。密码找回方式待决定。
- **商品发布**：填写标题、描述、价格、分类、成色、交易地点等信息并上传图片。必填字段、图片数量和大小待决定。
- **商品管理**：发布者查看自己的商品、编辑商品、下架商品；商品状态可区分在售和已下架。
- **浏览与搜索**：浏览在售商品，按关键词搜索；分类、价格排序或筛选是否纳入待决定。
- **商品详情**：显示商品描述、价格、图片、成色、发布时间和发布者公开信息。
- **收藏**：登录用户收藏商品、取消收藏并查看收藏列表。
- **基础管理**：至少有处理违规商品的管理办法。举报入口和审核是否在 MVP 上线前实现待决定。

### 3.2 暂不纳入第一版（后续候选）

- 站内即时聊天、消息通知
- 在线支付、平台担保、订单和退款
- 物流追踪、交易评价和信用分
- 个性化推荐、关注用户、复杂搜索排序
- 多校区／多学校运营和校园身份自动验证
- 数据分析后台及复杂运营活动

如果后续决定这些功能属于上线必需项，应重新调整 MVP 范围。

## 4. 核心用户流程

### 4.1 注册

1. 用户打开注册页，填写所需账号信息。
2. 网站检查字段是否完整、格式是否有效，以及账号是否已被使用。
3. 用户提交后，服务器再次校验并安全保存账号信息。
4. 网站提示注册成功，并引导用户登录或直接进入已登录状态（待决定）。

注册字段、校园身份验证方式及是否要求验证邮箱或手机号待决定。

### 4.2 登录与退出

1. 用户输入账号和密码。
2. 网站验证账号信息；失败时给出不泄露账号是否存在的提示。
3. 成功后建立登录状态，并提供退出入口。
4. 退出后，受保护的操作（如发布和收藏）需要重新登录。

### 4.3 发布商品

1. 登录用户进入发布页。
2. 填写商品信息并选择图片。
3. 网页先做基本检查，服务器再检查字段、价格和图片文件。
4. 保存成功后显示商品详情或发布成功提示。
5. 商品可直接展示，或先进入待审核状态；审核策略待决定。

### 4.4 搜索商品

1. 用户打开商品列表页，输入关键词，可选择分类或筛选条件（如 MVP 支持）。
2. 网站返回符合条件且当前可见的商品。
3. 用户可打开某件商品的详情。
4. 无匹配结果时显示清楚的空结果提示，并允许修改搜索条件。

### 4.5 查看商品详情

1. 用户从列表或收藏列表进入商品详情页。
2. 页面展示商品信息、图片、在售状态和发布者允许公开的信息。
3. 用户可收藏商品；未登录用户点击收藏时，网站提示先登录。
4. 联系方式展示方式与访客是否可见待决定。

### 4.6 下架商品

1. 发布者在“我的商品”中选择自己发布的在售商品。
2. 点击下架，并确认操作。
3. 服务器确认当前用户是该商品发布者或管理员。
4. 商品状态改为已下架，不再出现在普通在售列表和搜索结果中；详情页如何展示下架状态待决定。
5. 发布者可否重新上架、是否允许彻底删除待决定。

## 5. 页面清单

| 页面 | 主要内容 |
| --- | --- |
| 首页 | 搜索入口、商品分类入口、最新或推荐商品（推荐逻辑可先简单展示）。 |
| 注册页 | 注册字段、校验提示、登录入口。 |
| 登录页 | 账号和密码输入、错误提示、注册入口。 |
| 商品列表／搜索页 | 搜索框、筛选条件（如纳入 MVP）、商品卡片、分页或加载更多。 |
| 商品详情页 | 图片、标题、价格、描述、成色、地点、发布时间、发布者公开信息、收藏入口。 |
| 发布／编辑商品页 | 商品字段、图片上传、校验错误和提交反馈。 |
| 个人中心 | 账号基本信息、进入我的商品和我的收藏的入口、退出登录。 |
| 我的商品页 | 当前用户发布的商品、商品状态、编辑和下架入口。 |
| 我的收藏页 | 当前用户收藏的商品及取消收藏入口。 |
| 管理页面（基础） | 管理员查看和处理举报或违规商品；是否属于 MVP 待决定。 |

## 6. 核心数据与关系

- **用户（User）**：代表一个平台账号，保存登录所需信息和必要的公开资料。密码应保存为不可逆的安全摘要，不能以明文保存。
- **商品（Product）**：每件商品有唯一标识，并记录标题、描述、价格、分类、成色、地点、图片引用、状态、发布时间和发布者。
- **收藏（Favorite）**：表示某个用户收藏了某件商品，至少关联一个用户和一个商品，并记录收藏时间。同一用户对同一商品通常只保留一条收藏记录。
- **图片（ProductImage）**：图片记录归属于一件商品，可保存文件存储位置及展示顺序；图片文件本身通常存储在文件或对象存储中，数据库保存其引用。

关系概览：

- 一个用户可以发布多件商品；每件商品只有一个发布者。
- 一个用户可以收藏多件商品；一件商品也可以被多个用户收藏。收藏记录用来表示用户与商品之间的多对多关系。
- 一件商品可以有多张图片；每张图片属于一件商品。
- 商品至少需要有状态，例如“在售”“已下架”；是否需要“待审核”“已售出”“违规隐藏”等状态待决定。

## 7. 安全与个人信息保护

### 7.1 用户认证

- 密码不得明文保存，应使用专门的密码哈希方法保存。
- 登录和注册接口应限制频繁尝试，降低撞库和暴力猜密码风险。
- 登录凭证应安全传输和保存；退出登录后应使凭证失效。
- 错误提示不要透露过多账号状态信息。

### 7.2 权限校验

- 服务器每次都要检查当前用户是否登录、是否有权执行操作。
- 普通用户只能编辑或下架自己发布的商品，不能通过修改请求中的商品编号操作他人商品。
- 管理员权限应单独控制，并限制能授予管理员身份的人。

### 7.3 输入验证与常见攻击

- 浏览器和服务器都应检查必填项、长度、价格范围、字段格式；服务器检查是最终依据。
- 展示用户输入的文字时应正确转义，降低跨站脚本攻击（恶意内容被当作网页代码运行）的风险。
- 数据库查询应使用安全的参数化方式，避免把用户输入拼接成查询语句。
- 对登录、发布、收藏和举报等接口设置合理的请求频率限制。

### 7.4 图片上传

- 限制允许的图片格式、单张大小和数量；不要只相信文件名后缀，应检查实际文件类型。
- 重新生成安全文件名；图片应安全存储和提供访问，避免被当作可执行文件运行。
- 根据需要压缩图片并去除可能暴露拍摄地点等信息的元数据。
- 防止超大文件、伪造格式和恶意文件造成服务负担或安全问题。

### 7.5 个人信息保护

- 只收集完成服务所需的信息，并清楚说明哪些信息会公开。
- 不要默认公开手机号、真实姓名、学号等敏感信息；联系方式展示规则需由产品负责人决定。
- 使用 HTTPS 保护传输中的信息；限制员工或管理员访问用户数据，并保留必要的操作记录。
- 制定账号注销、数据保留与删除规则，并确认适用的隐私要求。

## 8. 第一版与后续功能边界

| 第一版 MVP | 后续候选 |
| --- | --- |
| 注册、登录、退出 | 邮箱／手机号找回密码、校园身份自动认证 |
| 发布、编辑、下架商品 | 重新上架、已售出状态、商品变更审核 |
| 商品列表、关键词搜索、详情 | 高级筛选、排序、个性化推荐 |
| 收藏与收藏列表 | 收藏降价提醒、关注卖家 |
| 基础管理违规内容 | 完整举报工作流、信用体系和运营后台 |
| 展示经确认可公开的联系信息 | 站内聊天、订单、支付、退款、物流、评价 |

## 9. 仍需产品负责人决定的问题

1. **服务范围**：面向一所学校还是多所学校？是否需要限制学校邮箱或校园身份验证？
2. **访客权限**：未登录用户能否浏览详情和看到联系方式？哪些操作必须登录？
3. **注册信息**：需要哪些字段？如何验证邮箱、手机号或校园身份？
4. **交易联系**：买卖双方通过公开联系方式、站内消息还是其他方式联系？
5. **商品字段**：分类、成色等级、交易地点和价格规则如何定义？是否允许免费或面议？
6. **图片规则**：每件商品最多几张图？单张大小和允许格式是什么？
7. **商品状态**：是否需要待审核、已售出、隐藏等状态？下架后能否重新上架或删除？
8. **审核与举报**：商品是否先审核再展示？用户如何举报？谁负责处理？
9. **搜索体验**：MVP 是否需要分类筛选、价格筛选、排序和分页？
10. **账号与隐私**：是否需要找回密码、注销账号？公开资料和交易数据保留多久？
11. **管理员范围**：谁能担任管理员？管理员可以采取哪些内容和账号处理措施？
12. **上线环境**：目标设备以手机还是电脑为主？上线地区、预算和预期用户规模是什么？

在这些问题确定前，可以先将它们作为实现前的决策清单；文档中的 MVP 建议不代表这些未决事项已获确认。
